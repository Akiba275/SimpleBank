## ATM 放置与交互

- 目标地图是村长家室内，即游戏当前版本中对应的 `Maps/ManorHouse`。
- 必须检查目标版本的实际地图、墙体、家具、碰撞层、事件区域和 Lewis/NPC 的移动路线后自行选择固定坐标；不要凭记忆猜测。优先选择靠墙、不挡门、不挡家具、不占 NPC 路径且玩家可从相邻格面对的位置。
- 在 README 和代码常量中清楚记录地图资源名、ATM 占用格、交互格及选择理由。若坐标需要因小版本差异调整，应集中在一处配置，不能散落硬编码。
- ATM 建议为两格高或与原版室内比例协调的壁挂/落地设备。生成原创、清晰、无第三方版权素材的像素贴图，视觉上与原版小镇室内的色板、轮廓、光照和像素密度协调；包含屏幕、卡槽或按键等可辨识细节，但不要直接复制游戏或其他模组的现有贴图。保持最近邻缩放、透明背景、整数像素边界，不得出现插值模糊。
- 使用 Content Patcher 的窄范围 `EditMap`/当前官方推荐机制添加贴图和必要的 tile 属性。不要覆盖目标区域之外的 tile 或 tilesheet 数据。
- 优先使用 Stardew Valley 1.6/SMAPI 支持的原生自定义 tile action 注册机制，将 ATM 交互注册为唯一 action（例如命名空间化的 `..._ATM`），避免不必要的 Harmony 补丁。若当前 API 不支持，再采用最小、可解释且兼容的替代方案。
- 玩家站在相邻可达位置，面对 ATM 并按正常“操作/使用工具”交互键即可打开菜单。鼠标右键/点击、键盘操作键与手柄 A/确认键都必须走同一业务入口；不得要求手柄用户使用鼠标。
- 进入地图或地图资产失效重载后，检查 ATM action 是否存在。若被其他地图补丁覆盖，写一条清晰但不刷屏的警告日志；不要崩溃或修改其他模组的数据。
- 仅当玩家在正确地图、正确 ATM 附近且可操作时打开界面；事件、过场、玩家失去控制、菜单已打开等情况下遵循游戏原生交互限制。

## 账户归属与多人规则

账户拓扑必须跟随该存档的原版钱包模式，而不是用模组自定义开关：

- 原版共享钱包：全农场共用一个活期账户、定期存单集合和贷款；任一玩家通过 ATM 看到和操作同一份银行数据。贷款额度使用主存档/农场对应的历史总收益。
- 原版独立钱包：每位玩家按稳定的 multiplayer ID 拥有独立的活期账户、定期存单集合和一笔贷款；额度使用该玩家自己的历史总收益。
- 不得以显示名作为持久化主键。
- 主机是银行存档和交易的唯一权威。客户端只提交带唯一交易 ID 的请求；主机重新校验账户归属、金额、余额、贷款额度、期限、状态和数据版本后原子执行，再同步结果。防止重复消息、双击、延迟重发或两名玩家并发造成重复入账。
- 为账户数据维护单调递增的 revision；陈旧请求应被拒绝并刷新 UI。所有错误须以本地化消息返回，不能仅写日志。
- 存档中途切换原版共享/独立钱包是边缘情况：不得静默复制、删除或重复银行资产/债务。至少应检测模式变化、阻止会导致资产复制的交易并给主机明确警告；如果实现自动迁移，必须是主机端、幂等、可测试且在 README 中精确说明合并/拆分策略。优先保证绝不复制金币。

## 金额模型与“总收益”不变量

- 游戏钱包金额使用游戏当前的规范类型；银行内部金额使用可安全覆盖更大范围的整数类型（优先 `long`），利率计算使用 `decimal`，并使用 checked arithmetic、上下界校验和清晰的溢出处理。不要用 `float`/`double` 处理金钱。
- 所有业务金额必须为正整数金币。贷款申请金额还必须是 1,000 金的整数倍。拒绝零、负数、无法解析、超过余额/额度、导致钱包或账户溢出的操作；失败必须是原子的，不能部分扣款。
- “总收益”指目标 Stardew Valley 1.6 运行时中代表历史累计收益的规范字段（通常为 `Farmer.totalMoneyEarned` 或其当前等价物），不是当前钱包余额。请检查当前 API/反编译签名后使用正确字段。
- 存款、取款、贷款发放、还款，以及银行利息的任何转移，都绝不能改变相关玩家/农场的历史总收益。
- 将所有钱包改动集中到一个经过测试的事务边界中：在改动前保存规范总收益值，使用正确的钱包 API 改钱，随后恢复/验证总收益；只在银行交易期间保护该字段，绝不能拦截正常种植、出售、任务等游戏收入。若共享钱包涉及多个统计字段，按当前游戏实现保护正确的规范字段集合。
- 为上述不变量编写测试或可运行的测试替身，并在调试日志中对异常变化给出诊断。不得通过全局、长期覆盖总收益来“修复”数值。

## 每日结算与日期

- 使用游戏的绝对日期/总天数表示开户日、已结算日和到期日；正确跨越季节、年份和 28 日边界。
- 开户/放贷当天不立即计息，从下一次日结开始。每次睡觉跨日后、玩家获得控制前完成一次结算；可使用当前 SMAPI 官方推荐的 `DayStarted` 或等效安全事件。
- 每日利息为整数金币。每一天都以 `decimal` 计算后使用明确、统一且可测试的规则四舍五入到整数（`MidpointRounding.AwayFromZero`）；随后再进入下一日复利计算。UI 和 README 必须说明该规则。
- 存档记录最后成功结算的绝对日。重复载入同一天不得重复计息；若模组停用数日后重启或一次跨过多日，按日顺序补算，不漏算也不重复算。
- 结算是主机端幂等操作。先在内存中完整计算并验证，再一次性提交和保存；异常时不得留下半结算状态。

## 活期存款

- 玩家可随时把当前钱包金币存入活期，也可随时从活期取回钱包。
- 活期每日复利：每次日结按当日开始时的活期余额和当前 GMCM 活期日利率计算，整数利息计入活期余额。
- GMCM 修改活期利率后，从下一次尚未执行的日结开始生效，不追溯已结算日期。
- 默认活期日利率为 `0.01%`。配置和 UI 中均以“每日百分比”展示，内部统一转换为 decimal 比例，避免把 `0.01%` 错当成 `1%`。

## 定期存款

- 默认启用 5 档：

  | 期限 | 默认日利率 |
  |---:|---:|
  | 7 天 | 0.02% |
  | 14 天 | 0.03% |
  | 28 天 | 0.05% |
  | 56 天 | 0.08% |
  | 112 天 | 0.12% |

- 一个账户可同时持有多张定期存单。创建存单时从钱包扣除本金，并锁定期限、该档日利率、开户日活期日利率、开户日、到期日和唯一 ID；之后 GMCM 改动只影响新存单。
- 定期按锁定的定期日利率逐日复利。完成规定数量的日结后到期，本金和全部定期利息自动转入活期，并在下一次打开 ATM 时显示本地化通知/历史记录。
- 到期结转不得经过玩家钱包，因此不能影响总收益。
- 到期前允许提前支取，但必须先显示二次确认对话框，清楚列出：本金、已持有的完整计息天数、放弃的定期收益、按开户时锁定的活期日利率重算后的金额，以及确认/取消。
- 提前支取时丢弃已累计的定期利息，从原始本金出发，按开户时锁定的活期日利率和已经完成的计息天数逐日复利并按统一规则逐日取整；所得本金与重算利息转入活期，不直接进入钱包。
- 同一天开户后立即提前支取的完整计息天数为 0，返还本金到活期。

## 贷款

- 默认启用 3 档：

  | 期限 | 默认日利率 |
  |---:|---:|
  | 7 天 | 0.25% |
  | 28 天 | 0.20% |
  | 112 天 | 0.15% |

- 每个账户同一时间只能有一笔未结清贷款；共享账户中的所有玩家共享这一个限制。结清后方可再次贷款。
- 贷款发放到当前操作玩家的原版钱包，但必须保持总收益不变。
- 放贷时锁定期限、日利率、逾期倍数、放贷日、到期日和唯一 ID；GMCM 后续改动只影响新贷款。
- 正常期内按“当前未偿本金 × 锁定日利率”每日计入待还利息；这是本金上的日单利，已产生的利息不再生利息。
- 到期后不自动从钱包、活期或定期账户扣款，不没收资产。到期日之后的每个日结，日利率改为“锁定日利率 × 锁定逾期倍数”；默认逾期倍数为 `1.5`。到期前/到期后天数边界必须有测试。
- 玩家可随时部分或全部还款，资金来自当前玩家钱包；按“先待还利息、后未偿本金”的顺序分配。还款必须保持总收益不变。
- 还款金额超过总欠款时，不得多扣；UI 可自动限制到精确欠款或明确拒绝。全部结清后保留精简的历史记录并释放贷款资格。

### 贷款额度

使用以下公式，所有中间计算必须防溢出：

```text
rawLimit = BaseCredit + HistoricalTotalEarnings * EarningsRatio
creditLimit = min(AbsoluteCreditCap, floor(max(0, rawLimit) / 1000) * 1000)
```

- 额度只保留千位，始终以 1,000 金为一个变化单位。
- 默认：`BaseCredit = 5,000`、`EarningsRatio = 10%`、`AbsoluteCreditCap = 1,000,000`；三项均可通过 GMCM 调整。
- 可申请金额最少 1,000 金，必须为 1,000 的整数倍，且不得超过当前额度。
- 因同一账户只允许一笔贷款，额度校验在新贷款发放时进行；不得把已还利息计入历史总收益或贷款额度。
- UI 同时显示用于计算的历史总收益、当前贷款额度、已借本金、待还利息、到期日和逾期状态。

## GMCM 与配置校验

- GMCM 必须是可选软依赖。通过 `GetApi`/当前官方推荐方式检测；未安装、版本不兼容或 API 获取失败时只记录一次清晰提示，继续使用 `config.json`。
- 提供最多 10 个定期档位和 10 个贷款档位。分别用“启用档位数量”控制实际档数，默认启用 5/3 档；GMCM 中为每个槽位注册期限天数和每日利率。
- 允许配置：活期日利率、定期启用数量及 10 组期限/日利率、贷款启用数量及 10 组期限/日利率、基础额度、总收益比例、绝对额度上限、逾期利率倍数，以及合理的调试日志开关。
- 所有 GMCM 名称、说明和数值单位均本地化，并反复说明利率是“每日百分比”。例如用户输入 `0.25` 表示每日 `0.25%`，不是 `25%`。
- 保存配置时验证并规范化：启用数量为 1–10；期限为正整数；同类启用期限不得重复；利率和比例不得为负且有合理上限；基础额度/绝对上限不得为负；绝对上限至少能容纳基础额度经抹零后的结果；逾期倍数至少为 1。无效值不能导致崩溃、负债反转或金币复制，应回退到上次有效值/安全默认值并显示日志或 GMCM 提示。
- UI 中按期限升序显示档位，但不要因排序而把期限和对应利率错配。
- 定期和贷款合同保存各自的锁定值，使删档位、改期限、改利率或减少启用数量不会改变既有合同。

## ATM 界面与输入

- 实现一个符合原版菜单视觉语言的自定义 `IClickableMenu`（或当前官方推荐基类），至少包含“概览、活期、定期、贷款”四个页面/页签。
- 概览显示钱包、活期、定期总额、未偿贷款、今日/下次日结提示和当前账户归属（共享或个人）。
- 所有操作都有即时校验、清晰反馈和本地化确认；高风险操作（提前支取，建议也包括新贷款）有二次确认。发送主机请求期间禁用重复提交并显示等待状态。
- 键鼠：鼠标悬停、点击、滚轮，键盘方向键/Tab 导航，Enter/Space 确认，Esc 返回/关闭；金额可键入，并正确处理退格、焦点和非数字输入。

- 使用游戏 UI 坐标系和当前 UI viewport；菜单尺寸根据可用区域计算并居中，在窗口尺寸或 UI scale 改变时重排。不要把 1920×1080、100% UI scale 或固定物理像素作为前提。

- 在支持安全区域/标题安全区的平台 API 可用时遵守其边界。

## 存档、兼容与安全性

- 通过 SMAPI 的 per-save data API 保存，不直接修改原版存档 XML。数据至少包括 schema version、钱包模式、账户、活期余额、定期合同、贷款合同、最近结算绝对日、revision、已处理交易 ID 的有限幂等记录，以及必要的通知记录。
- 提供版本化迁移入口。未知的新版本数据应安全失败并备份/保留原数据，不能重置账户。
- 仅主机写权威存档。处理断线、客户端重连、切换地点、当天重复开菜单、睡眠跨日和保存前同步。
- 对任意来自客户端的数据都不信任：重新解析、限制大小、校验 ID、账户权限、金额与状态。幂等 ID 缓存要有合理上限，避免存档无限增长。
- 日志不得包含隐私信息或刷屏；开发调试细节受配置开关控制。
- 尽量不使用 Harmony；若确实不可避免，说明原因、缩小补丁范围，并在启动时检测目标签名。

## 本地化

- 内置完整的简体中文与英文 i18n，覆盖菜单、按钮、金额单位、期限、利率、确认框、主机等待、配置项、验证错误、到期通知和兼容性警告。
- 默认语言回退到英文；不得把面向玩家的文本硬编码在 C# 中。
- 金额使用游戏/当前语言适合的分组格式；百分比和天数显示无歧义。

## 架构建议

保持职责清晰，具体命名可调整：

- `BankService`：纯业务交易和不变量。
- `InterestSettlementService`：按绝对日幂等补算。
- `CreditPolicy`：额度公式和抹零。
- `AccountResolver`：共享/个人账户归属。
- `SaveRepository`：版本化读写与迁移。
- `WalletAdapter`：唯一的钱包改动入口和总收益保护。
- `MultiplayerCoordinator`：请求、响应、revision、幂等和主机权威。
- `AtmMenu` 及页面/控件：只负责展示和输入，不直接改存档。
- `GmcmIntegration`：可选依赖与配置校验。

业务层不得依赖菜单；主机和单机必须调用同一套交易服务，避免两套规则漂移。

## 必测场景

至少为以下行为编写自动化单元测试；不能直接测试游戏类型的部分，使用窄接口/测试替身：

1. 额度公式在 0、低于千位、恰好千位、跨千位、达到上限及极大总收益时的结果。
2. 存款、取款、贷款发放、部分还款、全部还款前后，总收益完全不变；普通游戏收入不受该保护逻辑影响。
3. 余额不足、超额取款、超额度贷款、非 1,000 倍数、负数、零、溢出输入均原子失败。
4. 活期逐日复利和统一取整规则。
5. 五个默认定期档的到期日、跨季/跨年、自动转活期。
6. 提前支取在 0 天、1 天、到期前一天的重算和二次确认业务结果。
7. 贷款正常日单利、部分还款后次日利息、先息后本、到期日边界、逾期 1.5 倍、不产生利滚利。
8. 读档同一天不重复结息，漏过多日逐日补算，结算中失败不留下半状态。
9. GMCM 改动不影响既有定期/贷款合同，但影响新合同；档位排序不拆散期限与利率。
10. 共享钱包解析到同一账户，独立钱包按 multiplayer ID 隔离。
11. 重复交易 ID 只执行一次；陈旧 revision 被拒绝；并发请求不会双花。
12. 序列化往返、旧 schema 迁移和无效存档数据的安全处理。

此外给出游戏内手工验收清单，覆盖：

- ATM 在村长家的位置、碰撞、NPC 路径与地图冲突日志。
- 鼠标、键盘、Xbox/通用手柄完整操作。
- 四种 UI scale、窗口缩放与滚动列表。
- 单机、共享钱包联机、独立钱包联机、客户端重连。
- 睡觉后结息、定期到期、提前支取确认、贷款逾期和总收益 UI/统计值对比。
